# 课题 A：D455 RGB-D 人体状态检测

最终演示入口是 `preview_rgbd_v2.py`。它在原来的眨眼、活体判断和头部姿态
检测基础上，增加了多人主目标选择、低头报警、结果录制、事件日志和现场统计。

## 运行方法

在 PyCharm 中使用 `realsense` 环境的解释器
（`C:\Users\14010\Anaconda3\envs\realsense\python.exe`），把 D455 连接到
USB 3 接口，然后运行：

```powershell
python preview_rgbd_v2.py
```

运行前请关闭 Intel RealSense Viewer，避免相机被其他程序占用。

## 界面与操作

左侧是彩色画面和检测结果，右侧是与彩色对齐后的伪彩色深度图；视频下方是
4 列 × 3 行状态表，集中显示活体、头部状态（正常/低头/抬头）、眨眼、报警、
俯仰角、面部起伏、深度有效率、中心距离、人脸目标、处理帧率、录制和会话
统计。底部状态条用绿/黄/红区分“运行正常 / 眼部遮挡 / 低头报警”，文字
不再压在画面上。

| 按键 | 功能 |
|---|---|
| `N` | 正对相机时校准正常头部姿态 |
| `S` | 保存彩色图、16 位深度图和拼接预览图 |
| `R` | 开始或停止录制带检测结果和参数的 MP4 |
| `Q` / `Esc` | 退出程序 |

表中的“俯仰角”同时给出平滑值和原始值，“眨眼计数”同时给出 EAR 与基线；
另外还显示即时 FPS、FPS 中位数和 95 分位、头部切换次数以及报警次数。

## 实现说明

1. 面部区域深度先反投影成点云，再拟合平面并用法向量估计俯仰角，避免
   `solvePnP` 在近共面人脸点上出现镜像解跳变。
2. 头部姿态经过中值滤波、指数平滑、迟滞和连续帧确认，输出“正常/低头/
   抬头”；持续低头超过 `ALARM_HOLD_SECONDS` 后触发报警，只在真人状态下
   报警，抬头只显示和统计，不触发低头报警。
3. 眨眼检测使用自适应 EAR 基线（最近 150 帧的 80% 分位）；闭眼、恢复和
   最低点阈值分别为 0.80、0.85、0.78，冷却 0.25 秒、最长闭眼 1.0 秒，
   按真实时间而不是帧数判定，低帧率下连续快眨眼更稳定。
4. 主画面只绘制 124 条脸/眼/唇轮廓线，不再绘制 2556 条三角网格，减少
   每帧绘制耗时，为眨眼判定留出帧率余量。
5. 画面最多接收两张脸，选择面积最大的脸作为动作识别主目标，其余人脸只画框。
6. 双眼区域连续呈现“明显变暗且纹理很少”时提示眼部遮挡，暂停眨眼计数。
7. 活体判断先看面部有效深度占比，再根据点云相对平面的起伏区分真人和照片。

## 输出文件

所有结果写入运行目录下的 `captures/`：

- `events.csv`：校准、截图、录制、报警和会话结束事件，包含当时的关键参数。
- `session_summary.txt`：本次运行的帧数、人脸帧占比、头部切换、报警、眨眼和
  FPS 统计。
- `result_*.mp4`：按 `R` 录制的结果视频。
- `*_color.png`、`*_depth.png`、`*_preview.png`：按 `S` 保存的 RGB-D 截图。
- `*_alarm_*`：低头报警触发时自动保存的证据图。

## 实验报告建议

1. 真人/照片：各测试至少 30 次，记录漏判和误判，计算准确率、精确率、召回率。
2. 头部动作：低头、抬头各重复 30 次，记录检出延迟、状态切换次数和误报次数。
3. 眨眼动作：覆盖快、正常、慢三类动作，并补一组 0.6/0.9 秒间隔的连续快眨，
   比较计数结果与人工标注。
4. 适应性：分别在约 0.5、0.8、1.2 米，弱光、正常光、强光，以及纯色、
   杂乱静态、有人走动的背景下测试。
5. 对照实验：用相同录像比较 `preview_rgbd_vds.py` 和 `preview_rgbd_v2.py`
   的低头状态切换次数、报警延迟及误报情况；抬头状态只对 v2 单独统计。

## 注意事项

D455 的稳定深度距离约 0.45 米，演示时建议保持 0.5 米以上。眨眼依赖 EAR，
戴墨镜或严重遮挡时无法可靠计数；眼部遮挡提示和活体判断都是课堂演示级
启发式方法，不是安全级防伪系统。
